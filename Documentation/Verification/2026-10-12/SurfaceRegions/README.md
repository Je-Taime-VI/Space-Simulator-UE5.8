# 统一地表分区验证

执行日期：2026年10月12日，Asia/Shanghai。UE 5.8.2，SolarSystem地图，Win64编辑器。

## 实现与使用

规则源为 `Source/BigWorld/SolarSystem/SolarBiomeRules.inl`。C++与HLSL共用规则，分别通过小型数学/噪声适配器执行；轨道颜色、近地材质权重、WorldScape掩码与树草散布共同引用。规则输出为连续混合权重，不是互斥的贴图编号。

地球按纬度、海拔、坡度与程序化湿润度分布海岸、干旱区、植被区、岩地及雪区；火星、金星、月球和水星使用各自规则。当前温湿度是归一化分布指标，没有气候动力学、真实地理分类或季节变化。近地由实际坡面调整岩石/积雪，宏观颜色按零坡度分区；这一区别是细节层次，不是第二套气候规则。

修改规则后需要正式编译C++并运行 `Tools/refine_solar_materials.py` 刷新全部太阳系材质。只编译或只刷新近地 `M_Terrain` 都不足以同步所有使用方。地形高度函数、天体半径及太阳/曝光没有修改；材质重新保存了地图中的资产引用。

## 报告

- `SurfaceRegionsBuild.txt`：正式构建成功日志，随后重启编辑器。保留原有及共享浮点规则中的精度转换警告，不能描述为无警告构建。
- `RegionSamples.json`：5颗岩质天体各1024个均匀方向，共5120个样点。检查权重有限、非负、归一化，非地球无海水/植被，只有地球与火星允许雪层，以及提高坡度后露岩权重不减。分类统计按零坡度宏观权重，不能当作现实面积比例。
- `GpuParity.json`：40个样点逐点读回4×4 RGBA32F渲染目标，分别检查权重、温湿度/植被和颜色三组输出，共120条记录；不经过太阳照明、曝光或色调映射。最大差约1.95×10⁻⁶，阈值0.003，检查通过。高度与方向使用相同输入，验证的是分区规则适配器，不是全部地形生成误差。
- `before.json`、`final.json`、`Sites.json`：8个固定机位的实际Play记录，地球沙地/土壤/高地/雪面、月球、火星、金星及地球整球。每组对应 `Images/2026-10-12/SurfaceRegions/*-before.png` 与 `*-final.png`。
- `Comparison.json`：8组位置、方向、太阳照度、曝光及采样高度一致；另比对修改前备份，确认 `HeightKm`函数文本没有变动。
- `check.json`、`ExtraSites.json`：额外森林及干旱沙地的实际Play记录。森林374棵树、784组草，逐实例检查1158个点，未发现海水、明显积雪、沙地主导区或陡坡违规；干旱沙地无树草。
- `FinalAudit.json`：最终材质统计、诊断开关归零及既有天体模型验证通过。M_Terrain为2987条像素指令、11个采样器；M_Planet为2167条、M_Ocean为1144条。不是帧时间测量。

截图均为1280×720原始渲染，没有后期加工。固定模拟时间及输入进行采集；HUD海拔相对平均半径、速度显示控制器设定。旧机位名称保留，例如原 `earth-sand` 已因收窄沙带而变为土层过渡区。额外机位没有历史前图。

## 复核与边界

工具为 `Tools/verify_surface_regions.py`：`sample_catalogue()` 做模型抽样；`gpu_parity(rows)` 建立临时诊断材质并读回GPU输出，结束清理；`start_views('新阶段名')` 在实际Play会话中拍摄。机位配置优先读取Saved输出目录，缺失时读取本归档；不要覆盖历史阶段名。

额外两机位还调用 `audit_vegetation()` 核查实例落点。本次8组普通机位的报告生成于增加该检查钩子之前，因此逐实例结果只存在于 `check.json`，不能把它扩展为所有机位均做了实例审计。

纹理仍为上一轮10张资源、最高2K并流式加载。新增分区与坡度判断有计算开销，没有完成稳定前台帧率基准。原有平铺重复、clipmap几何/法线分界、云采样纹理、真实地形缺失及完整水体效果仍未解决；没有新增生态物种、实体岩石或气候模拟。

完整备份在 `Saved/Backups/SurfaceRegions_20261012`。回退须配套恢复源码、Shaders、材质工具及材质目录，重新编译并重启，避免CPU与GPU混用不同规则。验证结束后已退出Play并恢复编辑器原机位。
