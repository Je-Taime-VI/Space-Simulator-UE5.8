# 2026年10月18日｜海洋效果阶段一

本阶段接入WorldScape示例海面，并允许巡视相机进入海水。范围为自制SolarSystem地球；没有修改厂商示例地图、太阳曝光、云预算或行星地形高度。完整水下体积光学、浮力和交互尚未实现。

## 资源与实现

- 示例来源：`/WorldScape/Ressources/Materials/WorldScapeMaterials/Ocean/MI_Planetary_Ocean`，父材质为同目录`M_Water_WorldScape`。使用SingleLayerWater，包含两层程序化波浪、波浪法线、散射和吸收。
- 项目副本：`/Game/SolarSystem/Materials/M_Ocean_WorldScape`。采用示例实例参数，增加连续交接遮罩与行星尺度精度适配；插件和引擎原材质保持原样。
- `MF_OceanPerturbNormalHQ`为引擎函数的项目副本，只将求导坐标改为相机相对位置。波浪噪声在转为普通浮点前按128单位周期折回；本地引擎`Random.ush`的梯度纹理周期与整数倍频支持这一等价变换。只修正求导坐标仍存在网纹，噪声相位处理后近海画面中的规则细格消退。
- 波浪及近海光学在相机至表面距离5—20 km逐步淡出。海面和海底同步退出，远景球面的海洋遮罩互补，陆地仍走180—450 km交接。仅匹配海色、同步海底遮罩仍不足以消除高空边界；隔离隐藏水面组件后边界消失。正式构建在海拔20 km及以上隐藏已淡出的水面组件，并允许近景中的远景海洋覆盖。仍为连续飞行。
- 近海复测暴露出另一类网纹：远景球面启用后，默认0.3333裁剪阈值和时域抖动输出不能保证全隐端点。改为0.5中点阈值，并在最终遮罩上明确钳制全隐/全显；海面、海底、远景同时适配。远景交接距离另以视线与球形海面相交估算，减少粗三角面沉入海面产生的距离误差；单独修改距离没有消除网纹，不能将其记为根因修复。
- SingleLayerWater是水上表面路径；当前不绘制不透明背面，避免入水后整面遮黑。水下仰视可见天空，但尚无水下折射窗口、全反射或随深度变化的体积雾，因此不能称完整水下效果已经还原。

## 验证与原始文件

- `OceanBuild.log`：相机入水的BigWorldEditor Win64 Development正式构建成功，随后重启UE 5.8.2。`OceanCoverageBuild.log`：追加海面绘制退出和远景覆盖可见性后再次正式构建成功并重启；已有浮点转换警告保留。
- `before.json`：旧海面和旧移动限制的基线。
- `after.json`：初次接入示例，仍有近景网纹、远距着色边界和水下背面遮黑，不能作为最终通过证据。
- `precision.json`：只改法线求导与远距波浪衰减，近景网纹仍存在。
- `wrapped.json`：进一步修正噪声相位，近海定点对照。
- `final.json`：增加远距海色匹配、移除背面遮黑后的中间检查；仅匹配颜色仍未消除高空边界。
- `accepted.json`：仅修改海面及远景覆盖的中间版本，仍能看见多边形边界；没有作为最终通过状态，也不能据此确认海底为根因。
- `release.json`：同步海底遮罩后仍有边界；随后隔离隐藏水面组件时边界消失，不能将此问题仅归为海底。
- `verified.json`：正式编译重启后，300 km多边形色差消失，但近海仍有细网纹。`grid-isolation.json`隐藏远景球面时网纹消失，仅为诊断，不作为最终画面；`grid-visible.json`恢复可见后的对照保留。
- `spherical.json`：仅改球面交点距离，网纹仍在。`threshold.json`：裁剪阈值改为0.5后密集网纹消退，仍有零星漏点，因此追加明确的端点钳制。
- **`endpoints.json`与`*-final.png`：正式构建基础上完成最终材质端点修正后的6机位采集。** 覆盖近岸、海面、海下20 m平视/仰视、20 km和300 km。拍摄时冻结天文时间与输入，不冻结材质波浪时间，波峰位置并非逐帧一致。
- 最终近海同机位中密集细网纹和孤立青色漏点消失，近岸波浪保留；300 km未再出现本次引入的多边形色差。`boundary-final.json`追加19.99/20.01 km地平线视角，未见明显退出跳变。此前`boundary.json`为俯视机位，受原有雾状遮盖限制。
- `RetainedSpeed.json`：原有持续调速的17项回归通过，包括松开保持、双键恢复、30/60/144 Hz注入步长一致性及陆地防穿透。没有注入实体键盘，也没有把注入频率当渲染FPS。
- `ModelValidation.json`：现有太阳系模型校验成功。`MaterialFinal.json`为最终材质状态与编译统计；静态指令数不等于帧耗时，没有稳定FPS或显存峰值结论。
- `DemoOceanAudit.json`和`DemoWaterGraph.json`保留示例读取结果；`Material.json`为初次接入统计。`Manifest.json`记录原始路径、归档路径及SHA-256；截图直接复制，没有修改像素。

## 入水移动证据

检查点纬度−14.3764063°、经度109.7449119°，平均海平面下约146.293 m为程序化海底。调用与正常Q/E共用的C++移动入口，以20 m/s从海拔10 m向下运动3秒：

- 改动前停在海拔约3 m，不能穿过海面。
- 改动后到达约−50 m；继续下降停在海底上方约3 m；反向移动回到约96.707 m。
- 海平面附近仍保留自动减速；手动速度不会因松开调节键恢复自动。地表书签仍在海面或陆地上方生成。

改动前的水下截图由脚本直接摆放相机获得，用于比较背面外观，**不代表旧移动逻辑能够入水**。没有改动前通过实际下降到水下的截图；移动结论使用上述真实函数调用结果。防穿透仍是径向高度约束，不是航天器、人物或船体的物理碰撞。

## 已知限制与下一步

20 km固定机位在改动前后均被大面积雾状颜色遮盖，不能用这一机位宣称全部高空云与海水合成已验收。300 km用于检查本次新增的海面着色边界；其他纬度、天气、昼夜及高速飞越尚未全面验证。保持`r.VolumetricRenderTarget=0`与`r.SkyAtmosphere.AerialPerspectiveLUT.FastApplyOnOpaque=0`。

示例本身采用程序化波浪，不等于流体仿真。本阶段没有海岸破碎浪/泡沫、湿沙、潮汐、船尾流、浮力、水下体积雾、深海照明或海面物理碰撞；波浪高程和海底约束分别计算。下一阶段优先建立球形海洋的水下判定与视觉过渡，再做岸线细化和交互，见I-013。

维护入口为`Tools/refine_solar_ocean.py`，退出PIE后运行`main()`；两个总生成器与地表单独重建入口均保留海面覆盖适配。验证脚本`Tools/verify_solar_ocean.py`，归档脚本`Tools/archive_ocean_checks.py`。备份在`Saved/Backups/Ocean_20261018`：回退需同时恢复相机/星系C++、材质生成脚本、原地图、`M_Planet`和`M_Terrain`；原`M_Ocean`资产保留。不要撤销此前的云、大气和星环修正。
