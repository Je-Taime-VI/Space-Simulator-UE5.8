# 云层稳定性验证

日期：2026年10月16日。引擎：UE 5.8.2；地图：SolarSystem。

## 结果与范围

正式C++构建成功，重启自动读入体积渲染目标1、模式3；地球与金星视线倍率0.25。最终30项截图采集完成，组件显示、材质体积云用途及配置断言通过。图像复核中，金星月牙轮廓的明显阶梯和地球整球规则重建网纹消除。

5个机位为金星月牙、地球整球、地球20 km、地球5 km云内、金星58 km云内。每处采集静止、四个平移阶段和返回原位。截图使用正常视口Shot，1376×808，保留实际时域渲染，不使用HighResShot；HUD速度不代表脚本平移速度。只覆盖这些机位，尚无急转、连续穿越全云层、云地遮挡、所有帧率或平台的完整验收。

## 文件

- `comparison.json`：旧密度材质下，模式0/倍率0.5与模式3/倍率0.25的60条记录。
- `comparison_gpu.json`：上述每个固定机位的一次GPU云事件。
- `final.json`：三维密度烘焙、正式构建重启后30条记录，采用工程实际设置。
- `FinalGpu.json`、`GpuEvents.txt`：最终单次GPU云事件及原始日志行。
- `Build.txt`：正式构建成功日志；仍存在原有插件与代码浮点转换警告。
- 精选前后图位于`Images/2026-10-16/CloudStability`，完整采集帧位于`Saved/Diagnostics/CloudStability`。

初次测试发现UE Python一元负号会原地修改Vector，使相机朝向设置错误；该无效采集标记失败，放在Saved的`invalid-camera-comparison`，未用于本记录。最终工具用乘以负一替代。

## 性能证据与限制

最终云GPU事件单次抽样：金星月牙6.417 ms、地球整球1.611 ms、地球20 km 5.255 ms、地球云内3.284 ms、金星云内6.812 ms。不得把这些值当作稳定帧时间或推算游戏FPS；首次使用、后台时钟及编辑器双视图会影响测量。

烘焙前的模式3、倍率0.25在地球20 km机位为20.920 ms；烘焙后首次复查为8.716 ms，正式重启后为5.255 ms。不同抽样有波动，因此只说明本次测量中密度计算成本明显降低。旧模式0同机位5.482 ms，不能据此宣称新方案在所有机位都更快。

新增64³ G8体积纹理在运行资源列表中记录384 KB，使用两层周期噪声的离线近似与三线性采样。它不等同于旧函数逐点结果。全分辨率渲染目标也增加资源占用；未记录峰值显存，未进行真实天气与云形美术验收。

## 技术依据与回退

本地`VolumetricRenderTarget.cpp`中模式3逐像素追踪并跳过云专用重建，仍保留整个场景的时域抗锯齿。Epic的[UE-388559](https://issues.unrealengine.com/issue/UE-388559)另记录UE 5.8远距离几何上的双边上采样砖块伪影，目标修复版本6.0；此项仅为相关证据，不是全部现象的唯一根因证明。

备份为`Saved/Backups/CloudStability_20261016`。回退须恢复配置、C++采样预算、云材质、着色源与生成器后正式编译。新增的两个纹理资产若不再引用可留存，不必为回退删除。世界地形、海水、昼夜光照与曝光规则未在本轮修改。
