# WorldScape Plugin 生产级接入实战（中文自写教程）

> 资产编号：UE-PLG-0050  
> 本文在官方能力之上给出项目化实施方案，重点是可维护、可测试、可回退。

## 1. 实战目标

以“生成真实行星与近乎无限世界的地形、体积、噪声、植被和重力系统。”为目标，先完成一个独立演示关卡，再通过 WorldScapePluginAdapter 接入正式玩法。资产的六项核心能力为：行星地形、无缝大世界、程序噪声、植被流送、世界体积、重力与示例角色。

## 2. 目录与职责

```text
Content/Project/WorldScapePlugin/Config/
Content/Project/WorldScapePlugin/Data/
Content/Project/WorldScapePlugin/Runtime/
Content/Project/WorldScapePlugin/UI/
Content/Project/WorldScapePlugin/Tests/
Source/ProjectRuntime/*/WorldScapePluginAdapter
```

Config/Data 只保存可审计配置；Runtime 负责状态和适配；UI 不直接修改资产内部数组；Tests 保存最小地图、压力地图、网络地图和验收记录。

## 3. 第一次接入

1. 先建立独立性能测试地图，只启用 行星地形，使用固定种子或固定预设保证每次结果可比较。
2. 把区域、网格、生成规则和资源集合放入数据资产或配置表，不把大批规则硬编码在关卡蓝图。
3. 建立 WorldScapePluginAdapter 统一控制生成、刷新、暂停、销毁和状态查询，明确服务端与客户端各自负责的范围。
4. 为 无缝大世界、程序噪声 和 植被流送 设置数量、距离、每帧耗时、内存和队列上限，超限时采用分帧或降级。
5. 用低速、快速穿越、地图切换、存档读取和多人迟加入场景验证生成结果、持久状态和视觉效果。
6. 发布前在干净环境运行长时间 soak test，记录峰值 Actor 数、Game Thread、GPU、内存、GC 和卸载后残留。

## 4. 状态机

使用 Disabled → Initializing → Ready → Running → Succeeded/Failed 的主流程，并允许 Running → Cancelling → Ready。所有状态变化只由 WorldScapePluginAdapter 发出，Widget 和关卡对象订阅项目事件。重复点击、回调晚到、地图切换和对象销毁都不能跳过清理步骤。

## 7. 保存与升级

只保存稳定 ID、业务状态、配置版本和必要参数，不保存显示文本、临时对象路径、数组下标或委托句柄。加载时先验证 schema_version，再执行迁移；遇到未知 ID 进入兼容分支并记录，不直接崩溃。升级前固定旧包和项目提交，升级后运行相同测试矩阵，失败可立即回退。

## 8. 安全与性能

- 文件、网络、玩家输入和外部数据都按不可信处理。
- 路径规范化并限制到批准目录；网络事件由服务端复算权限。
- 队列、缓存、实例和每帧工作必须有上限。
- 不在 Tick 中扫描全部对象；使用事件、分区、定时器或分帧任务。
- 记录 Game Thread、GPU、内存、GC、队列和网络带宽。
- Shipping 不输出敏感配置、绝对路径和大段业务数据。

## 9. 自动化与人工测试

1. 单元级：配置验证、稳定 ID、状态转换、错误映射。
2. 集成级：行星地形、无缝大世界、程序噪声 的组合闭环。
3. 压力级：最大数量、快速输入、长时间运行和反复加载卸载。
4. 生命周期：地图切换、对象销毁、退出和崩溃恢复。
5. 网络级：双客户端、迟加入、断线重连和权限拒绝。
6. 发布级：Development、Shipping、干净环境和目标平台。

## 11. 常见失败

最常见问题不是“节点不会用”，而是边界不清：Widget 直接写业务数组、Level Blueprint 持有长期状态、异步回调没有代次、服务端不复算权限、缓存无上限、升级后稳定 ID 改名。发现异常时先恢复到最小闭环，逐项重新启用能力。
