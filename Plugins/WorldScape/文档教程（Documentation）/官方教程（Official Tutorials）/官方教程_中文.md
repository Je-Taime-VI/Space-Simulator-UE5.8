# WorldScape Plugin 官方教程整理（中文）

> 资产编号：UE-PLG-0050  
> 整理日期：2026-07-19  
> 依据 Fab 官方商品页、发布者维护文档和公开演示资料整理。资产包与引擎的对应关系以本资产 metadata 和交付目录为准。

## 1. 资产定位

生成真实行星与近乎无限世界的地形、体积、噪声、植被和重力系统。

官方公开能力重点包括：

- 行星地形
- 无缝大世界
- 程序噪声
- 植被流送
- 世界体积
- 重力与示例角色

本文不是商品简介，而是可直接执行的集成教程。建议先在独立分支和空白测试项目完成最小闭环，再迁移到生产地图。

## 2. 官方入口

- Fab 商品页：https://www.fab.com/listings/0ef85bf8-a0be-4b74-87f8-b66bb44d6ae2
- 官方文档或发布者维护教程：https://iolacorp.com/worldscape-plugin-documentation/

本地只归档官方明确提供下载的文档文件；对于在线文档，交付目录保存轻量 HTML 入口和来源记录，不抓取整站页面资源。

## 3. 安装与源文件确认

1. 关闭 Unreal Editor，选择与目标引擎对应的交付包。
2. 解压后保留完整插件顶层目录，不混用其他引擎包的 Binaries、Source、Content、Resources 或 ThirdParty。
3. 项目级安装放入 Project/Plugins；引擎级安装保持 Marketplace 目录结构。
4. 检查 .uplugin 的 FriendlyName、VersionName、Modules、LoadingPhase 和目标平台。
5. 启用资产后重启编辑器，查看 Output Log 最早出现的错误，确认没有模块、父类或资源缺失。
6. 在空白地图运行官方示例或最小测试，不先改生产关卡。

## 4. 最小可运行闭环

1. 先建立独立性能测试地图，只启用 行星地形，使用固定种子或固定预设保证每次结果可比较。
2. 把区域、网格、生成规则和资源集合放入数据资产或配置表，不把大批规则硬编码在关卡蓝图。
3. 建立 WorldScapePluginAdapter 统一控制生成、刷新、暂停、销毁和状态查询，明确服务端与客户端各自负责的范围。
4. 为 无缝大世界、程序噪声 和 植被流送 设置数量、距离、每帧耗时、内存和队列上限，超限时采用分帧或降级。
5. 用低速、快速穿越、地图切换、存档读取和多人迟加入场景验证生成结果、持久状态和视觉效果。
6. 发布前在干净环境运行长时间 soak test，记录峰值 Actor 数、Game Thread、GPU、内存、GC 和卸载后残留。

## 5. 推荐项目结构

```text
Source/ProjectRuntime/Public/Services/WorldScapePluginAdapter.h
Source/ProjectRuntime/Private/Services/WorldScapePluginAdapter.cpp
Content/Project/WorldScapePlugin/Config/
Content/Project/WorldScapePlugin/Examples/
Content/Project/WorldScapePlugin/Tests/
Saved/Diagnostics/UE-PLG-0050/
```

Blueprint 项目也应保留同样的边界：Subsystem/Component 负责资产调用，Data Asset/Data Table 保存配置，Widget 只消费快照与结果事件，Level Blueprint 不保存长期服务状态。

## 6. 配置方法

1. 复制官方默认配置形成项目预设，不直接修改唯一原件。
2. 为 行星地形、无缝大世界、程序噪声 建立明确命名的配置组。
3. 所有资源引用优先使用软引用；批量加载前先计算数量和内存预算。
4. 数值范围提供下限、上限和默认值；非法值在进入资产逻辑前拒绝。
5. 调试显示、详细日志和性能统计只在开发配置启用，Shipping 默认关闭。
6. 保存配置版本号和迁移函数，升级后不依赖旧蓝图节点的隐式默认值。

## 7. 生命周期与错误处理

运行时状态至少区分 Disabled、Initializing、Ready、Running、Cancelling、Succeeded、Failed、ShuttingDown。每次操作生成 request_id；当回调返回时必须确认请求代次和 UObject 仍有效。

地图切换、PIE 结束、Actor 销毁、玩家退出和应用关闭时，依次停止新请求、取消任务、解绑委托、清理计时器、释放句柄。错误按配置、输入、权限、资源、网络/依赖、超时、取消和内部错误分类，UI 显示可操作提示，日志记录阶段和错误码，不记录密钥或隐私数据。

## 8. 性能与多人

- 对 行星地形 设置数量、并发和每帧预算。
- 对 无缝大世界 记录 Game Thread、GPU、内存、GC 和队列峰值。
- 大批工作分帧执行；缓存必须有容量和淘汰策略。
- 多人状态由服务端权威推进，客户端输入必须重新验证。
- 至少用两个独立进程测试，不用单进程 PIE 代替网络验收。
- 迟加入客户端接收完整状态快照；断线重连不重复创建业务对象。

## 9. 测试矩阵

- 首次安装、启用、编辑器重启和项目重开
- 行星地形、无缝大世界、程序噪声、植被流送、世界体积、重力与示例角色
- 空输入、非法输入、极限数量、取消、超时和依赖缺失
- 地图切换、对象销毁、反复进入退出和应用关闭
- 双客户端、迟加入、所有权变化和断线重连（如适用）
- Development 与 Shipping 包、干净用户环境和目标平台
- 新旧资产包升级、旧配置/存档迁移和回退

每条测试记录前置条件、输入、期望、实际、日志、引擎包、资产包和结果。

## 10. 打包验收

1. 固定项目提交和资产包 SHA-256。
2. 清理项目自身的临时构建残留后重新打包，不删除资产包内部文件。
3. 在干净环境启动 Development 与 Shipping 成品。
4. 验证核心闭环、失败闭环、地图切换、保存读取和目标平台依赖。
5. 检查日志不含敏感信息，错误提示可定位。
6. 执行一次升级和一次回退演练。

## 11. 常见排错顺序

1. 核对引擎包、资产版本和目标平台。
2. 核对完整顶层目录、模块或 Content 挂载路径。
3. 读取第一条相关错误，不只看最后的 Packaging Failed。
4. 在空白项目复现，排除项目配置和其他资产冲突。
5. 减少输入，关闭扩展功能，只保留最小闭环。
6. 对照当前官方文档替换旧节点、旧属性或旧配置。

## 12. 完成定义

- 正常、失败和取消流程均可重复。
- 资产调用集中在项目适配层。
- 关键配置、稳定 ID、生命周期和测试记录齐全。
- Development 与 Shipping 在干净环境通过。
- 官方入口、包、校验值和回退路径可追溯。
